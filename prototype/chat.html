Spring Boot 性能调优 · 6 周学习计划

基于知识库 6 篇高相关度文档整理，按「先度量、再定位、后优化」的顺序推进。每周预留 6–8 小时，含实验任务与验收指标。

1 第 1–2 周：建立度量与观测基线

  • 接入 Micrometer + Prometheus，暴露 /actuator/prometheus 端点，确认 JVM、HTTP、连接池三类指标可采集。
  • 使用 JMeter 建立 3 组压测基线：50 / 200 / 500 并发，记录 P95、P99 与错误率。
  • 开启 GC 日志（-Xlog:gc*:file=gc.log），确认单次 Full GC 时长与频率。

2 第 3–4 周：连接池与 SQL 治理

观测项 采集方式 建议阈值
连接等待时长hikaricp.connections.pending< 10 ms
慢 SQL 数量druid.sql.slow.count< 5 条 / 分钟
P99 响应耗时http.server.requests< 300 ms

连接池参考配置（需结合压测结果调整，不要直接照搬）：

spring:
  datasource:
    hikari:
      maximum-pool-size: 32        # 约 2 × CPU 核数
      minimum-idle: 8
      connection-timeout: 3000

      max-lifetime: 1740000        # 小于数据库 wait_timeout

3 第 5–6 周：灰度验证与回归

  • 按 5% → 30% → 100% 三档灰度放开优化后的实例，比对 P95 与错误率。
  • 建立回归压测任务，纳入 CI，指标劣化超过 10% 时阻断发布。
